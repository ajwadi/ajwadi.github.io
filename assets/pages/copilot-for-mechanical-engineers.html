Before we startGround rules

Never paste in

  • Customer or OEM confidential drawings and specs
  • Proprietary part numbers, formulations, or process settings
  • Supplier pricing, quotes, or contracts
  • Warranty or complaint data with names
  • Passwords or system credentials

Safe to use

  • General engineering concepts and public standards topics
  • Made-up or anonymized sample data
  • Generic geometry and dimensions
  • Your own macro or script code with no proprietary details
  • Templates, checklists, and outlines
Engineering judgment stays with you. Copilot can be confidently wrong. Check every calculation, tolerance, and standard reference before it is used.
~1.5 min. Our rule: no company sensitive data in Copilot. Everything in today's demos is made up. If you are unsure whether something counts, treat it as sensitive. Anonymize: swap real part numbers for "Part A", real suppliers for "Supplier 1".

Better promptsThe GCSE formula

G

Goal

What do you want? An email, a summary, a macro, a chart.

C

Context

What is the situation, and who is it for? Supplier, manager, shop floor.

S

Source

What should it use? Pasted data, a file, a website.

E

Expectations

Format, length, tone, units, level of detail.

This is the structure Microsoft recommends for Copilot prompts. Think of it like a good engineering change request: the more complete the input, the less rework on the output.

~1.5 min. Most bad results come from missing Context or Expectations. For engineers, "Expectations" often means units, tolerances, and format, such as "metric, 2 decimal places, as a table".

See the differenceWeak prompt vs. strong prompt

Weak

"Write an email to the supplier about the bad parts."

Copilot has to guess which parts, what is wrong, what you want them to do, and by when.

Strong 
[G] Draft an email to our bracket supplier
[C] reporting that 12 of 200 parts from the last shipment measured out of tolerance on the mounting hole position. We need containment and a corrective action plan.
[S] Use the anonymized inspection summary I pasted below.
[E] Professional, under 150 words, list 3 clear asks with a response date of Friday.
~2 min. Run both live if time allows. Then show the follow-up trick in the same chat: "Make it firmer" or "Add a subject line".

HTML tools for engineers

Ask Copilot to write the HTML. Save it. Open it in your browser. Done.

Transition. Have Copilot Chat open in another tab, ready to paste the prompt.

The basicsWhat is an HTML file, really?

It is a small app that runs inside your web browser. One file holds three layers:

HTMLThe structure: headings, tables, buttons, input boxes.
CSSThe look: colors, fonts, layout, spacing.
JavaScriptThe behavior: calculations, charts, clicks, filters, 3D.

Why engineers like it

  • Runs in Edge or Chrome. No install, no license.
  • One file you can email or drop in a Teams channel
  • People without CAD or Excel skills can still use it
  • Can work fully offline if built without web links

Know the limits

  • No shared database: data lives in the file or what you load
  • Very large datasets can get slow
  • Libraries loaded from the web need internet
  • A quick tool, not a validated system of record
~2 min. Key message: you do not need to code. You need to describe what you want and know how to save a file. Point out the last limit: an HTML tool is great for analysis and communication, but it does not replace controlled documents or validated quality systems.

The possibilitiesWhat you can build with one HTML file

📈

Interactive charts

Pareto charts, defect trends, and control charts with limits. Hover for values, filter by line or shift.

🧮

Engineering calculators

Tolerance stack-ups, bolt torque, unit conversions, material weight from volume and density.

🧩

Open an STL or GLB export in the browser, rotate, isolate parts, and measure. Great for suppliers and the shop floor.

📊

Dashboards from CSV

Drop in a CSV export and KPIs, tables, and charts update on the spot.

✅

Checklists and forms

Drawing checks, layered process audits, and trial checklists that export results to a file.

📝

Interactive work instructions

Step-by-step pages with images, warnings, and a "mark complete" button for each step.

~2 min. Every one of these is a single prompt away. The 3D viewer is a strong example: it lets people who do not have CAD software look at a part, isolate components, and measure. Ask: which of these would save you time this month?

Step 2Save it and open it

Option A: no installs
  1. Click Copy on Copilot's code block
  2. Open Notepad and paste
  3. File > Save As, set type to All files, name it defects.html
  4. Double-click the file to open it in your browser
Option B: VS Code
  1. New file, paste the code
  2. Save as defects.html
  3. Open it in your browser (or use the Live Server extension)
  4. Edit and refresh to see changes
Blank page? Check the name did not become defects.html.txt, and that you are online (the chart library loads from the web).
~1.5 min. Do Option A live since everyone has Notepad. The .txt trap is the most common issue, so show "All files" clearly.

Step 3The result

Line 3 Defects by Type, Jan to Jun

~1.5 min. Built into the slide as a backup in case the live demo is slow. Hover the bars, then switch to Pareto. Ask: where would you focus? Weld leaks and wall thickness make up about 60% of defects. Dimensional issues spike in April.

Step 4Keep asking for changes

Follow-up prompts that work

  • "Add a target line at 20 defects per month."
  • "Add a control chart view with upper and lower limits."
  • "Let me load a CSV export instead of pasted data."
  • "Add a button to download the chart as a PNG for my report."

When something breaks

  • Describe what you see: "The page is blank."
  • Press F12, copy the red error, paste it back in.
  • Ask: "Fix it and give me the full updated file."
For deeper analysis of an Excel file of test data, try the Analyst agent. It can run the numbers and explain trends.
~1 min. Key habit: always ask for the full updated file so nobody is merging code by hand.

The ideaWhat is an agent?

A version of Copilot you set up for one job, so you stop re-explaining the same rules every time. Like a trained team member who already knows your standards.

Instructions

Who it is, what it does, how it answers, and what it must never do.

Knowledge

Approved files, templates, or pages it should draw from.

Starter prompts

Ready-made buttons so others know how to use it.

Built by Microsoft

Researcher for multi-source reports. Analyst for data and trends. More in the Agent Store.

Built by you

Create agent in Copilot for focused helpers. Copilot Studio for advanced workflows, usually with IT.

~2 min. A normal chat is like briefing a new temp every time. An agent already knows the job. Quickly show Researcher on a public topic if time allows, such as "trends in lightweight plastics for automotive".

Real exampleA CATIA Macro Assistant

Repetitive CATIA work is a perfect fit for VBA macros. An agent that knows our macro conventions can write and debug them in minutes.

Macros already built this way

  • Random colorizer: a different color per part, so assemblies are easy to read
  • Component renamer: bulk rename parts and files
  • Tree exporter: product structure to CSV
  • Tree filter: show or hide parts matching a pattern
  • Box generator: a grid of test parts in a product

Build it in 5 minutes

  1. In Copilot, go to Agents and choose Create agent
  2. Describe it: "Helps our engineers write and debug CATIA V5 VBA macros"
  3. Open Configure and paste the instructions (next slide)
  4. Add knowledge: your approved macro templates, with no proprietary data
  5. Add starter prompts, test in the preview, then Create and share
~3 min. Explain the value: each macro used to mean searching forums and trial and error. With an agent that already knows the rules (unique names, form plus module, error handling), the first draft is usually close. Then build it live.

Live buildThe instructions and starter prompts

You are "CATIA Macro Assistant" for our engineering team.
Help engineers write, explain, and debug CATIA V5 VBA macros.

- Always return complete code: the module, and the UserForm code if there is a GUI, clearly labeled.
- Use Option Explicit, clear comments, and error handling with a friendly message.
- Give every public Sub and Function a unique, macro-specific name so macros in one VBA project do not cause "Ambiguous name detected" errors.
- After the code, list the steps to add and run it (Tools > Macro > Visual Basic Editor).
- If a macro changes or deletes many items, warn first and suggest testing on a copy of the file.
- Never ask for or include proprietary part numbers, customer names, or drawings.

Starter prompts

  • "Give every part in the open product a random color."
  • "Export the product tree of the active CATProduct to CSV."
  • "Why do I get 'Ambiguous name detected'?"
  • "Add a simple form with a text box and a Run button."
Always test new macros on a copy of the file first.
~3 min. Paste the instructions, add the starter prompts, and test with "Give every part in the open product a random color." Point out the guardrail lines: unique names, test on a copy, no proprietary data.

FOR MANAGERSWhat managers can look into

KPI dashboards

HTML dashboards for scrap, first pass yield, or open actions, built from regular CSV exports.

Shared team agents

One approved agent per repeat task, such as macros, 8Ds, or onboarding, instead of everyone prompting differently.

A team prompt library

Collect the prompts that work in a shared page so good results are repeatable.

Run a small pilot

3 to 5 engineers, one month, track hours saved on specific tasks.

Set clear data rules

Write down what can and cannot go into Copilot, and who reviews shared agents.

Meeting follow-through

Use Teams recaps after design reviews so actions and owners are captured every time.

~2 min. The biggest wins come from consistency: shared agents and a prompt library mean the whole team benefits, not just the early adopters. A short pilot with measured time saved makes the case for wider rollout.
